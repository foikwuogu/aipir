# AIPIR Zero-Trust controls

AIPIR treats every request as untrusted until proven otherwise. These controls map to NIST
SP 800-207 (Zero Trust Architecture) tenets and to the SOW's MFA, RBAC, and IAM items.

| Control | How AIPIR implements it | Where |
|---|---|---|
| Every request authenticated | Every API endpoint except `/healthz` needs a signed bearer token. Tokens are checked for issuer, audience, expiry and signature. HS256 is accepted only in lab mode; RS256 is used with an identity provider. An HS256 token offered to an RS256 verifier is rejected. | `framework/aipir/zerotrust.py` |
| IAM (identity provider) | Entra ID app registration with app roles, role assignment required, one group per role, and a workload identity for Alertmanager. No client secrets are created in Terraform. | `deploy/terraform/modules/entra-zero-trust` |
| MFA | Conditional Access requires MFA for every human sign-in to the AIPIR API. The service also checks `amr` contains `mfa` for sensitive actions (request, approve, configuration, baseline). | Entra module + `rbac_policy.yaml: mfa_required` |
| RBAC, least privilege | Five roles with explicit permissions; unknown roles grant nothing; there is no admin bypass (admins cannot approve recoveries). Human roles never apply to workload tokens, and the reverse. | `rbac_policy.yaml` |
| Separation of duties | Two-person rule: a recovery is approved by someone other than the requester. The service enforces it, and the Ansible playbooks enforce it again. | `zerotrust.py`, `ansible/roles/ot_restore` |
| Kubernetes RBAC | The detector has no Kubernetes API token. The drift checker is read-only. The recovery runner can only patch the detector deployment. People get namespaced roles through groups. | `terraform/modules/aipir-k8s-rbac`, `k8s/base/10-rbac.yaml` |
| Micro-segmentation | Default-deny NetworkPolicy. The detector accepts traffic only from the monitoring namespace and may reach only DNS and the OTel Collector. It never reaches the control network. | `k8s/base/30-network-policy.yaml`, detector module |
| Hardened workloads | Non-root, read-only root filesystem, all capabilities dropped, seccomp RuntimeDefault, restricted pod-security namespace. | Manifests, modules |
| Continuous verification | Short-lived tokens (15 min by default in the lab). Prometheus authenticates its scrapes. An alert fires when scraping fails. | `prometheus.yml`, `alert_rules.yml` |
| Tamper-evident audit | Every allow and deny decision and every recovery transition is written to a JSON-lines log. Each entry carries the SHA-256 of the previous one (`python -m aipir.zerotrust verify-audit <file>`). Entries are also exported as OpenTelemetry logs. | `zerotrust.py`, `otel.py` |
| Integrity of configuration | Signed (Ed25519) configuration baseline and drift check. Recovery refuses a setpoint baseline whose hash does not match. | `framework/aipir/drift.py`, `ansible/roles/ot_restore` |

## Roles

| Role | Who | Can | MFA |
|---|---|---|---|
| `aipir.viewer` | Control-room and engineering staff | read metrics and status | - |
| `aipir.operator` | Shift engineers | request a recovery, acknowledge alerts | required |
| `aipir.recovery-approver` | Second person (supervisor or reliability lead) | approve a recovery someone else requested | required |
| `aipir.admin` | Platform owners | change configuration, refresh the drift baseline | required |
| `aipir.alert-relay` | Alertmanager (workload) | submit recovery requests | n/a (workload) |
| `aipir.metrics-scraper` | Prometheus / OTel Collector (workload) | read metrics | n/a (workload) |

## Service settings

| Variable | Lab | Pilot / production |
|---|---|---|
| `AIPIR_AUTH_MODE` | `hs256` | `rs256` |
| `AIPIR_ISSUER` | `aipir-lab` | `https://login.microsoftonline.com/<tenant-id>/v2.0` |
| `AIPIR_AUDIENCE` | `api://aipir` | the app's identifier URI, e.g. `api://aipir-pilot` |
| `AIPIR_LAB_SECRET` | generated by `deploy/compose/gen-lab-secrets.sh` | not set |
| `AIPIR_JWKS_FILE` | - | the tenant's JWKS (`.../discovery/v2.0/keys`), refreshed on key rotation |
| `AIPIR_POLICY` | default `deploy/zero-trust/rbac_policy.yaml` | site copy under change control |
| `AIPIR_AUDIT_LOG` | local file | persistent volume, shipped to the SIEM via OTel logs |
| `AIPIR_ENV` | `lab` | `production` (disables lab token minting) |

Authentication cannot be switched off. With no verifier configured, every protected request is
refused.

## What remains for the site

- Decide the group membership for each role, and name break-glass accounts for the MFA policy.
- Run the MFA policy in report-only mode first, review the sign-in logs, then enable it.
- Store recovery credentials in a vault, and give the Alertmanager identity a certificate or
  federated credential.
- Keep the policy file, site inventory, and signed baselines under management of change.
